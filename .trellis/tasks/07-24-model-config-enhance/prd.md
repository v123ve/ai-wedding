# 模型配置页面增强

## Goal

优化后台模型配置管理体验，减少手动输入错误，提升操作效率。

## Requirements

### R1: 拉取模型列表并选择
- 用户输入 API Base URL 和 API Key 后，点击按钮可拉取该服务商下的可用模型列表
- 模型名称从手动输入改为下拉选择
- 支持 OpenAI 兼容格式的 `/v1/models` 端点
- 加载过程中显示 loading 状态
- 拉取失败时显示友好错误信息

### R2: 测试连接
- 用户可点击"测试连接"按钮验证 API Base URL + API Key 的有效性
- 测试时调用模型列表接口作为连通性验证
- 显示测试结果（成功/失败+错误信息）
- 测试过程中按钮显示 loading 状态，不可重复点击

### R3: 编辑时默认激活
- 新建模型配置时，状态默认为"激活"（active），而非"停用"（inactive）
- 编辑已有配置时保持原有状态不变

### R4: 选择类型时自动设置名称
- 当用户选择配置类型时，如果当前名称为空，自动填入对应的中文标签
- 如果用户已经手动修改过名称，则不覆盖

## Constraints

- 不修改现有数据库模型（不新增字段）
- 复用现有 Prisma enums 和类型定义
- API Key 始终只从客户端传到服务端，不持久化在客户端
- 遵循现有项目代码风格

## Acceptance Criteria

- [ ] 在 API Base URL + API Key 输入框下方有"获取模型列表"按钮，点击后填充模型下拉框
- [ ] 模型下拉框可选择，选中后填入 model_name 字段
- [ ] "测试连接"按钮可工作，显示明确的成功/失败结果
- [ ] 新建配置默认状态为"激活"
- [ ] 选择"图片生成"类型时名称自动填入"图片生成"
- [ ] 选择"其他"类型时名称自动填入"其他"
- [ ] 所有操作有 loading 状态反馈
- [ ] lint + typecheck 通过
